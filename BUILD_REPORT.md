## Issues Found and Fixed

### 1. Font loading — CSS import order (Task 3)

**Issue:** `apps/website/src/app/globals.css` (and the identical pattern
in `apps/platform` and `apps/dashboard`) had the Google Fonts `@import`
placed *after* the `@tailwind base/components/utilities` directives.
Per the CSS specification, `@import` statements must precede all other
statements in a stylesheet — this is an import-order violation.

**Fix attempted (preferred option):** Migrated to `next/font/google`
for Inter in all three apps (added the loader in each `layout.tsx`,
exposed a `--font-inter` CSS variable, updated each `tailwind.config.ts`
`fontFamily.sans` and each `globals.css` `body` rule to reference it,
and removed the CDN `@import`).

**Result:** `pnpm build` failed in this verification environment —
`next/font/google` fetches font files from `fonts.googleapis.com` at
build time, and that domain is not reachable from this environment's
network egress allowlist:

```
Error [NextFontError]: Failed to fetch font `Inter`.
URL: https://fonts.googleapis.com/css2?family=Inter:wght@400;500;600;700;800&display=swap
Please check if the network is available.
```

Since this couldn't be verified to actually pass here, the change was
reverted rather than shipped unverified.

**Fix applied (fallback option, verified):** Moved the existing Google
Fonts `@import` line so it directly follows the
`@import '@phoenix/design-system/tokens.css';` line and precedes all
`@tailwind` directives, in all three apps'  `globals.css`. Re-ran the
full pipeline (`type-check`, `lint`, `build`) after this change — all
passed. This is the "alternative" option explicitly named in the task
brief when `next/font` isn't usable.

**Files changed:**
- `apps/website/src/app/globals.css`
- `apps/platform/src/app/globals.css`
- `apps/dashboard/src/app/globals.css`

No other font-related files (`layout.tsx`, `tailwind.config.ts`) were
changed in the final state — they were reverted to their original
content after the `next/font/google` attempt was rolled back.

### 2. Missing `packages/analytics` (Task 2)

**Issue:** `packages/analytics` did not exist in the workspace, despite
being referenced in the acceptance criteria as a required placeholder
package.

**Fix:** Added `packages/analytics/package.json`,
`packages/analytics/src/index.ts`, and `packages/analytics/README.md`,
matching the existing conventions used by `packages/config` and
`packages/core` (no vendor integration, no `tsconfig.json` at the
package level, `main`/`types`/`exports` pointing at `./src/index.ts`).
Exports `trackEvent()`, `identifyUser()`, and the `AnalyticsEvent` /
`AnalyticsUser` types, all as safe no-ops.

No other issues were found. `pnpm type-check`, `pnpm lint`, and
`pnpm build` all passed on the first attempt, before any code changes,
for the pre-existing codebase.
