# Browser QA Report — PHX-PREVIEW-001

**Project:** Phoenix Website (phoenix-website-launch-candidate)
**Environment:** Ubuntu 24 container, Node v22.22.2, pnpm 8.15.9, Next.js 14.2.35
**Local URL used:** `http://localhost:3005` (production build served via `next start -p 3005`; port 3005 used in place of the framework default to avoid conflicts with other apps in the monorepo)

---

## Commands Run

```
pnpm install
pnpm --filter=./apps/* type-check
pnpm --filter=./apps/* lint
pnpm --filter=./apps/* build
cd apps/website && next start -p 3005
```

Note: the root `dev` script (`pnpm --filter @phoenix/website dev`) targets the website app directly; for QA we used a production build (`build` + `start`) rather than `dev` so that screenshots and console-error checks reflect what will actually ship.

## Install Result
- `pnpm install`: **Success.** 378 packages added across 9 workspace projects (6 packages + 3 apps). One pre-existing lockfile-compatibility warning (lockfile generated by a different pnpm version) — resolved automatically by pnpm on install, no manual intervention required.

## Build Result
- `pnpm --filter=./apps/* type-check`: **Pass** — 0 errors across `apps/website`, `apps/platform`, `apps/dashboard`.
- `pnpm --filter=./apps/* lint`: **Pass** — "No ESLint warnings or errors" for all three apps.
- `pnpm --filter=./apps/* build`: **Pass** — all three apps compiled successfully.
  - `apps/website`: 13/13 static pages generated (8 content routes + `/`, `/_not-found`, `/icon.svg`, `/sitemap.xml`). All routes prerendered as static content (○).
  - First Load JS shared by all: 87.3 kB (website).

## Runtime Result
- `next start -p 3005`: server started in ~345ms, `Ready` confirmed.
- All 8 required routes returned **HTTP 200**: `/`, `/platform`, `/pbrs`, `/products`, `/solutions`, `/resources`, `/about`, `/contact`.

## Known Issues
- None blocking. One enhancement noted: the `/contact` form explicitly discloses it is a UI preview not yet wired to a backend — accurate as shipped, but worth tracking as a pre-launch follow-up if live submission is required at launch.
- Local tooling note (not a product defect): this environment's cached Playwright/Chromium build initially mismatched the npm-installed `playwright` version, requiring a pinned `playwright@1.56.0` install to match the available browser binary. No impact on the website itself.

## Recommended Fixes
1. Wire the `/contact` form to its intended backend/CRM endpoint before public launch, or keep the current disclosure visible if launching with a placeholder form is intentional.
2. No code, architecture, or content changes are recommended for the 8 reviewed routes — the build is clean and ready for the next review gate as-is.

## Overall Verdict
**Preview build is stable, error-free, and visually consistent across all required routes and breakpoints. No architecture, PBRS model, or content changes were made during this QA pass, per task constraints.**
